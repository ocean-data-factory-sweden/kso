18. How are the models stored?

Current behaviour
• Each trainer’s 

save() method writes its checkpoint into the directory configured in project.yaml → output_dir (default ./outputs).
– TorchTrainer → outputs/model.pt (PyTorch state_dict).
– YoloTrainer → outputs/ folder produced by Ultralytics (weights .pt, YAML results).
– HFTrainer → outputs/hf_model/ (Hugging-Face save_pretrained format).

• After the file(s) are created you can pass the resulting path to the storage layer (
kso.storage.get_storage()) to keep a local copy or upload to S3, e.g.:

```python
from kso.storage import get_storage
store = get_storage()          # LocalStorage or S3Storage depending on configs/storage.yaml
artifact = trainer.save(Path(cfg.output_dir))
store.upload_file(artifact, f"{cfg.project_name}/{Path(artifact).name}")
```
Planned improvements
	1	Automate that last step inside save() so the trained weights are: • written to output_dir, and• automatically uploaded to the configured remote bucket if storage.remote is defined.
	2	Add metadata files (.json) in the same folder describing hyper-parameters and git commit for reproducibility.
If you would like the automatic upload implemented now just let me know which storage back-end(s) you plan to use.
